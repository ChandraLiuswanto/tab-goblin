## Release blockers reproduced

All were reported on bead `tabgoblin-server-browser-v7n` before any production edit. This task did not modify production code.

1. **History back times out.** After two successful static fixture navigations, `tabgoblin_back` deterministically returns `timeout_uncertain` instead of the prior page. A no-history `back` call succeeds, so all 25 tools are accounted for separately from this meaningful-history probe.
2. **Remote-CDP upload fails after staging.** A workspace-relative regular file is pinned and copied correctly into `/staging/meaningful-upload.txt`; `tabgoblin_upload` then returns `runtime_unavailable`. The host-side Playwright client is asked to resolve a container-only path.
3. **Durable plugin generations do not survive gateway restart.** Same-process plugin cleanup/reopen works. After restarting the gateway, persisted nonzero workspace/agent generations are rejected by its fresh in-memory enrollment registry, so `openSession` returns no scope. The test records this before using a separate fresh plugin-state directory to finish browser-profile checks.
4. **Tab IDs are recycled after restart.** A fresh browser attachment reuses at least one pre-restart lexical tab ID because its local counter restarts, so cached IDs can alias post-restart pages instead of disappearing.
5. **Default test command has a parallel filesystem race.** Protocol smoke removes `packages/protocol/dist` while the MCP bridge test independently builds against that package. The exact `npm test` gate is red even though the serial diagnostic passes.

## Operator-only follow-up

1. Rebuild the image and rerun the exact live command above. Remove the blocker-tolerant branches from the integration test and require successful history navigation, upload, durable plugin recovery, and disjoint post-restart tab IDs.
2. In actual Paseo web and desktop clients, enable the plugin for a disposable workspace; verify initial/manual refresh, status timestamp, tabs/activity, pairing expiry, retained-panel reopen messaging, and compact layout. Record the Paseo and phone versions.
3. With explicit consent, first record `tailscale serve status`, then configure the proposed loopback viewer mapping: `tailscale serve --bg --https=443 http://127.0.0.1:<viewerPort>`. Test from a real phone on the tailnet, including disconnect/reconnect and contention, then restore the operator's prior Serve configuration.
4. With explicit consent, install/enable the user unit, verify it directly, reboot, and repeat gateway/plugin/viewer/profile checks. Do not claim reboot persistence until that reboot has actually occurred.
